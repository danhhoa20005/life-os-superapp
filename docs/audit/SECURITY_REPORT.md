## 1. P0 Security Vulnerabilities Closed & Verified on Live Cloud Firestore Emulator

| Issue ID | Attack Surface | Previous Loophole (`v3.26.0`) | Hardened Enforcement (`v3.27.0`) | Verification Result |
|---|---|---|---|---|
| `AUD-001` | `families/{familyId}/funds/{fundId}` + `contributions` + `expenses` + `fund_audits` | Plain member could directly inflate/drain `balanceMinor`, auto-approve expenses on creation, self-approve, or delete fund history. | Enforced `balanceMinor == 0` on create; `balanceMinor` changes ONLY with atomic `!exists && existsAfter` `fund_audits/{lastAuditId}` math verification (`previous + delta == new`) linked to `contributions` or `expenses` (`approved -> executed` / `reversed`); full 9-state FSM (`draft -> pending_approval -> approved -> executed -> reconciled` + `rejected/cancelled/disputed/reversed`); separation of duties (`requesterId != auth.uid` for multi-member families); immutable `delete: if false` on audit/expense/contribution collections. | **PASS** (Emulator Attacks 1 & 2) |
| `AUD-002` | `settlement_requests` & `settlements` | Debtor could unilaterally create confirmed `settlements` docs (forging fake debt onto victims) or replay unlimited `rev_*` contra-reversals; `'bank_transfer'` forgery allowed. | Forbade unilateral debtor creation and unverified `'bank_transfer'` writes; required creditor confirmation (`toUserId == auth.uid`) OR atomic `settlement_requests` (`pending -> confirmed`, deterministic `stl_req_<requestId>`); restricted reversals to deterministic single `rev_<origId>` by creditor/manager only; converted `confirmSettlementRequest` to `runTransaction`. | **PASS** (Emulator Attack 3) |

## 3. Privacy & Encryption Honesty Statement
- Document Vault files use authenticated local `AES-256-GCM` encryption (`"LOSV"` v1 format) with Android Keystore keys + `docId` AAD + SHA-256 read verification; bank queue SQLite payloads use `AES-256-GCM` with `"bank_queue"` AAD; backup `.lfbk` archives use `PBKDF2-HMAC-SHA256` + `AES-256-GCM` + `SHA-256`.
- Firestore cloud documents remain protected by TLS in transit, Google-managed encryption at rest, and strict RBAC `firestore.rules` — LifeOS does **not** falsely claim full cloud end-to-end zero-knowledge encryption for Firestore queries.
